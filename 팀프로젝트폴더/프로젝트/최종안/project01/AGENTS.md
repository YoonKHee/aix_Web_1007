# 프로젝트 목적

이 프로젝트는 K리그 데이터를 활용한 Django 프로젝트다.

주요 목표:
1. K리그1 선수 데이터를 관리한다.
2. 선수 능력치를 이용하여 Best11을 선정한다.
3. 구단별 Best11을 조회할 수 있게 한다.
4. 선수 공식 사진을 표시한다.
5. 경기 데이터를 활용하여 승/무/패 예측 기능을 개발한다.


# 가장 중요한 규칙

- 기존에 정상 작동하는 기능을 최대한 유지한다.
- 사용자가 요청하지 않은 기능은 임의로 수정하지 않는다.
- 기존 변수명, 함수명, 모델명을 특별한 이유 없이 변경하지 않는다.
- 대규모 리팩터링을 임의로 하지 않는다.
- 여러 파일을 수정해야 한다면 수정할 파일과 이유를 먼저 알려준다.

내가 "분석해줘"라고 하면:
→ 파일을 수정하지 말고 문제의 원인만 분석한다.

내가 "수정해줘"라고 하면:
→ 필요한 부분만 최소한으로 수정한다.


# 데이터 보호 규칙

선수 및 경기 데이터는 매우 중요하다.

다음 작업을 임의로 하지 않는다.

- 선수 데이터 삭제
- 구단 데이터 삭제
- 경기 데이터 삭제
- 데이터베이스 초기화
- migration 파일 삭제
- DB 파일 삭제
- 선수 ID 변경
- 기존 CSV 원본 데이터 수정

데이터 구조를 변경해야 한다면 먼저 이유와 영향을 설명한다.


# Django Model 규칙

주요 관계를 유지한다.

Team
↓
Player

Player는 Team과 ForeignKey 관계를 사용한다.

예:

Player
- name
- position
- age
- nationality
- shooting
- dribble
- passing
- defense
- minutes
- team → Team ForeignKey

ForeignKey 구조를 임의로 변경하지 않는다.

models.py를 수정할 경우 반드시 알려준다.

1. 변경 내용
2. 변경 이유
3. DB에 미치는 영향
4. makemigrations 필요 여부
5. migrate 필요 여부


# 선수 데이터 규칙

선수 이름만으로 동일 선수라고 판단하지 않는다.

가능하면 다음 정보를 함께 확인한다.

- 선수 ID
- 선수 이름
- 소속팀
- 포지션

선수 ID 충돌 가능성을 확인한다.

선수 데이터가 서로 다른 구단에 잘못 연결되지 않도록 확인한다.


# 선수 사진 규칙

선수 사진을 수정하거나 동기화할 때 다음을 확인한다.

선수
→ 선수 ID
→ 선수 이름
→ 소속팀
→ 공식 선수 정보
→ 사진

이름만 같다는 이유로 사진을 연결하지 않는다.

기존에 정상적으로 연결된 선수 사진을 임의로 덮어쓰지 않는다.

사진이 없는 경우 임의의 다른 선수 사진을 사용하지 않는다.


# Best11 규칙

Best11 계산 로직은 프로젝트의 핵심 기능이다.

Best11 관련 코드를 수정할 때 기존 계산 방식을 먼저 분석한다.

가중치를 임의로 변경하지 않는다.

가중치를 변경해야 한다면 다음을 비교한다.

기존 가중치
VS
변경 가중치

그리고 변경 전/후 선수 순위가 어떻게 달라지는지 보여준다.

예:

변경 전
1. 선수A
2. 선수B
3. 선수C

변경 후
1. 선수B
2. 선수A
3. 선수C

가능하면 순위 변화도 보여준다.

예:

선수A : 1위 → 2위 (-1)
선수B : 2위 → 1위 (+1)


# 포지션 규칙

Best11 선정 시 선수 포지션을 확인한다.

예:

GK
DF
MF
FW

서로 다른 포지션의 선수를 단순 총점만으로 비교하지 않는다.

현재 프로젝트에서 사용하는 포메이션과 포지션 선정 규칙이 있다면
그 규칙을 우선 유지한다.


# 구단 필터 규칙

사용자가 특정 구단을 선택하면
해당 구단 소속 선수만 사용하여 Best11을 계산해야 한다.

예:

전북 선택

전체 선수
→ 사용하지 않음

전북 선수
→ 필터링
→ Best11 계산
→ 전북 Best11 출력

구단 필터 수정 후에는 다른 구단 선수의 데이터가 섞이지 않는지 확인한다.


# 경기 예측 규칙

승/무/패 예측 기능을 수정할 때
학습 데이터와 평가 데이터를 구분한다.

미래 경기 결과를 예측할 때
실제로 경기 이후에 알 수 있는 데이터가 입력되지 않도록 확인한다.

데이터 누수(Data Leakage)가 발생할 가능성이 있으면 반드시 알려준다.

예측 모델을 변경할 경우 가능하면 다음을 비교한다.

- 기존 모델
- 새로운 모델
- Accuracy
- Precision
- Recall
- F1 Score

단순히 정확도가 높다는 이유만으로 좋은 모델이라고 판단하지 않는다.
